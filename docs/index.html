Autonomous AI Software Engineer View on GitHub

An agent that fixes the bug, then proves it with tests.

Give it a GitHub repo and an issue number. It reads the issue, explores the code, edits the files, and runs the tests in a Docker sandbox. If they fail, it reads the error and tries again. When they pass, it opens a pull request.

How one run works

    
Each step is a node in a LangGraph workflow that shares one state.

    
    
      
  1. 1
    Fetch the issueRead the title, body, and comments through the GitHub API, then clone the repository.
    2. 
      
  2. 2
    Run the testspytest runs inside a Docker container with no network access and a 512 MB memory limit.
    3. 
      
  3. 3
    Propose a fixGemini sees the issue, the source files, and the test output, and returns exact edits: file, old text, new text.
    4. 
      
  4. 4
    Apply the editsAn edit is applied only if the old text appears exactly once. Otherwise it is rejected and the error goes back to the model.
    5. 
      
  5. 5
    Check againThe tests run again. Passing ends the run; failing sends the new output back to step 3.
    6. 
      
  6. 6
    Open a pull requestThe agent creates a branch, commits the change, and opens a PR that references the issue.
    7. 
    

    
Steps 3 to 5 repeat up to a set number of attempts. The Python ast module also lets the agent outline every function and class in a file, with line numbers, without reading the whole file.

The harness fails a case if the agent edits the test files, because rewriting a test is not a fix. These are small, single-file bugs, so treat this as a sanity check, not a measure of performance on large real-world repositories.

What it can’t do yet

    
The limits I know about, and what I plan to fix first.

    
    
      
  • It supports only Python projects that use pytest.
    • 
      
  • It sends whole source files to the model, so large repositories need smarter file selection. Using the AST outline to pick files is the next step.
    • 
      
  • Fixes are verified only by the existing tests, so a weak test suite can let a wrong fix through.
    • 
      
  • It can clone only public repositories.
